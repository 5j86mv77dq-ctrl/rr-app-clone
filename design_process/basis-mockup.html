    vision.md · the tie-breaker

    Relevant Radio App — North Star

    One place where the Relevant Radio audience prays, listens, and watches — live first, on-demand always, personal where it matters.

    • Live is the front door — one tap from open to live prayer, radio, or video.
    • On-demand is the library — everything re-watchable and re-listenable.
    • Prayer is scheduled life — reminders that meet the day, not interrupt it.
    • Accounts serve continuity — resume, favorites, downloads; never a wall.

    Deliberately not: a social network, a third-party podcast aggregator, or a paywall.

    The actual Vision (index.html) embedded live — local file, not a screenshot.

    Manual

    Work done outside the ritual is not recorded: the changelog, the staleness pins, and the board go wrong silently. Four steps, every time.
    1Pick a sliceFrom the Slices board. Check its status and base first. New idea → New slice: <idea> instead.
    2Open the sessionClick into the slice, copy its session prompt, paste into Claude Code.
    3IterateProduct language only. Review on local (instant) or share (~30s after push).
    4Close the sessionSay close session — log, funnel triage, board update, push. Skipping this is what breaks the system.
    Commands
    • open session — recap; pick a page.
    • Plain English — “make the prayer card bigger.” Edited, render-verified, pushed.
    • New slice: <idea> — one-off (off current production) or chain step; created as draft.
    • Chop up <big feature> — define steps together (MVP first); only step 1 gets built.
    • funnel to main — port pending slice changes into the Vision.
    • serve local — start the local preview server (localhost:8000).
    • close session — log, triage changelog, update the board, push.
    • “X is now production” · “dev team started X” · “X shipped” · “retire X” — statuses move only when you announce reality.
    Rules
    • One git branch (main). Claude runs all git.
    • Every page is render-verified before push. Broken = one revert (~30s).
    • in dev and later = frozen. No edits without explicit OK.
    • Chains: never more than 3 unshipped steps deep.
    • Reference docs: CLAUDE.md · Roadmap/README.md · Roadmap/CHANGELOG.md.
    Statuses
    • prodA designation, not a stage. One slice at a time — the mirror of the real app. Default base for one-offs.
    • draftBeing built. Edit freely.
    • in reviewWith Father Rocky. Light edits only.
    • in devWith the dev team. Frozen spec — no edits without explicit OK.
    • shippedLive in the real app.
    • plannedA chain step not created yet.
    • staleThe base moved since this slice was copied. Run an assessment.
    Terms
    • The Vision — index.html. The end-state. Never overwritten; absorbs approved slice ideas.
    • Slice — one buildable stage, copied from its base. Own URL.
    • One-off — one small feature, copied from current production.
    • Feature chain — a large feature chopped into ordered steps.
    • Funnel — porting a slice's keeper ideas into the Vision.
