User Manual

Re-entry

  1. Read the list above. Status + Updated = the full project state.
  2. Open Claude Code: Mac app → RR App Clone folder. Or claude.ai/code → the GitHub repo.
  3. Say open session.

Terms

  • The Vision — index.html. The end-state. Never overwritten; absorbs approved slice ideas.
  • Slice — slices/<name>.html. One buildable stage, copied from its base. Own URL.
  • Current production — the slice with the green tag. Closest mirror of the real app today. Default base for one-offs. Exactly one at a time; moves when reality moves.
  • One-off — a single small feature (e.g. a call-in button). Copied from current production; inherits everything, adds one thing.
  • Feature chain — a large feature chopped into ordered slices (step 1 = MVP, ships first; step 2 copies step 1; …). Grouped on this board under the feature name.
  • Funnel — porting a slice's keeper ideas into the Vision.

Statuses

  • visionThe Vision only. Permanent.
  • current productionA designation, not a stage. One slice at a time. Default base for one-offs.
  • draftBeing built. Edit freely.
  • in reviewWith Father Rocky. Light edits only.
  • in devWith the dev team. Frozen spec — no edits without explicit OK.
  • shippedLive in the real app.
  • archivedRetired. Recoverable from git history.

A status is a label on this board — changing it sends nothing and notifies no one. Peter shares URLs himself. To change one, tell Claude: “Father Rocky has X” → in review · “dev team started X” → in dev · “X shipped” → shipped · “retire X” → archived · “X is now production” → moves the green tag.

Commands

  1. open session — recap; pick a page.
  2. Plain English — “make the prayer card bigger.” Edited, render-verified, pushed. Live in ~30s.
  3. New slice: <idea> — Claude asks: one-off (copies current production) or chain step (copies the previous step)? Creates the page as draft.
  4. Chop up <big feature> — define the steps together (MVP first); step 1 gets built; later steps get created as earlier ones stabilize.
  5. funnel to main — port pending slice changes into the Vision.
  6. serve local — start the local preview server (the local links; localhost:8000).
  7. close session — log, triage changelog, update this board, push.

Rules

  • One git branch (main). Claude runs all git.
  • Every page is render-verified before push. Broken = one revert (~30s).
  • in dev and later = frozen. No edits without explicit OK.
  • Reference docs in the repo: CLAUDE.md · Roadmap/README.md · Roadmap/CHANGELOG.md.
