User Manual

Re-entry

  1. Read the list above — base, dependencies, funnel, updated dates. Workflow status (review / dev / shipped) lives in ClickUp, not here.
  2. Open Claude Code: Mac app → RR App Clone folder. Or claude.ai/code → the GitHub repo.
  3. Say open session.

Terms

  • The Vision — index.html. The end-state. Never overwritten; absorbs approved slice ideas.
  • Slice — slices/<name>.html. One buildable stage, copied from its base. Own URL.
  • Current production — the slice with the green tag. Closest mirror of the real app today. Default base for one-offs. Exactly one at a time; moves when reality moves.
  • One-off — a single small feature (e.g. a call-in button). Copied from current production; inherits everything, adds one thing.
  • Based on — the file a slice was copied from, pinned in time. Lineage only — says nothing about ship order.
  • Depends on — what must ship before a slice can. A big feature is just slices linked by dependencies, MVP first; each later piece copies the piece it depends on once that stabilizes.
  • Front matter — every slice file opens with a <!--PROTO--> comment block (name · production · base pin · dependsOn). The per-file record; this page's MANIFEST is its index, updated in the same commit.
  • Funnel — porting a slice's keeper ideas into the Vision.

Tracking — what lives where

Workflow status (in review, in dev, shipped…) lives in ClickUp — this board deliberately does not track it. The repo carries only technical truth:

  • visionThe Vision (index.html) — the end-state page; never a slice.
  • current productionThe designation. One slice at a time — the mirror of the real app; default base for one-offs. Moves when you tell Claude “X is now production.”
  • staleComputed live from git: the base file changed since this slice's pin. Ask Claude to assess (cosmetic / structural / conceptual) before working on it.

Announcements that still matter to the repo: “X is now production” → moves the green tag · “X shipped” → refresh dependents' bases · “X is frozen for dev” → gap note; the file stops changing · “retire X” → archive the file.

Commands

  1. ⧉ on any row — copies that slice's session prompt; paste it into Claude Code to open a correctly-scoped session.
  2. open session — recap; pick a page.
  3. Plain English — “make the prayer card bigger.” Edited, render-verified, pushed. Live in ~30s.
  4. New slice: <idea> — Claude asks: one-off (copies current production) or a piece of a bigger feature (copies the piece it depends on)? Creates the page as draft.
  5. Chop up <big feature> — define the pieces together (MVP first); only the MVP gets built now; later pieces depend on it and copy it when it stabilizes.
  6. add loading + error states — wires the skeleton (pulsing) and failed-to-load treatments behind LOADING / ERROR demo pills on a page. Claude asks which file and which regions first, every time. Full prompt: Roadmap/prompts/loading-error-states.md.
  7. funnel to main — port pending slice changes into the Vision.
  8. serve local — start the local preview server (the local links; localhost:8000).
  9. close session — log, triage changelog, update this board, push.

Rules

  • One git branch (main). Claude runs all git.
  • Every page is render-verified before push. Broken = one revert (~30s).
  • in dev and later = frozen. No edits without explicit OK.
  • Reference docs in the repo: CLAUDE.md · Roadmap/README.md · Roadmap/CHANGELOG.md.
